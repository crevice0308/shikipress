# Targeted ShikiPress security and correctness review — 2026-11-01

Baseline: `39005246207e66ed6f709d6b5602c479d357b592` (theme 1.1.4).
Fresh public GitHub API check at 2026-11-01 05:48 UTC: main still matches baseline; no open PRs; latest listed compatibility/browser workflows on baseline completed successfully. This does not validate this local change.

No production site, real credentials, or third-party advertisement service was used. This is a targeted source review and isolated regression exercise, not a penetration test or a guarantee of absence of vulnerabilities.

## Confirmed findings and minimal changes

1. **TOC fragment encoding (functional/accessibility).** Existing author heading IDs such as `100%` threw URIError in the actual frontend JavaScript; `section%20literal` resolved the wrong target. Encode IDs when generating fragment URLs and tolerate malformed legacy fragment escapes in the click handler. Preserve existing IDs, design and features. Baseline separately failed both renderer and JS regression tests. This was not demonstrated as a security exploit.
2. **Development-only dependency advisories.** Nested Playground lock contained body-parser1.20.8, fast-uri3.1.8 and qs6.15.3. Updated to1.20.9/3.1.9/6.16.2. Express4.22.2 pins qs~6.15.3, requiring a narrow Express→qs6.16.2 override; no unrelated major upgrade or Playground downgrade. Official npm URLs and integrity hashes retained. These packages are not distributed in the WordPress theme ZIP. Relevant advisories: [body-parser DoS](https://github.com/advisories/GHSA-27r3-jxmh-p828), [fast-uri URI normalization](https://github.com/advisories/GHSA-w74x-v6f9-j3xg), [qs](https://github.com/advisories/GHSA-6pq8-jhm2-2vcw). Lock audit changed from3 vulnerable packages (1 high,2 moderate) to0; this is a point-in-time registry result, not a source security proof.

## Security entrypoints reviewed

- `inc/core.php`: Settings API schema and known sections, manage_options, REST exposure disabled; prepare-pages admin-post capability+nonce.
- `inc/tools.php`: all six admin-post actions (scan/external/export/preview/apply/restore); operation nonce+manage_options; known-key/type/size/depth import validation, private value rejection, separate unfiltered_html executable-code import, user-scoped preview+HMAC+apply revalidation, execution disarming. External link validation rejects credentials, private/reserved IPs, unsafe schemes/ports and ambiguous hosts; cURL DNS pinning and each-hop redirect checks reviewed statically.
- `inc/automation.php`: authenticated slug-suggest/title-translation/status/category-slug AJAX; edit_post/manage_categories and nonce gates; fixed DeepL endpoints, explicit consent, bounded retries and stale-owner CAS. Public view-count REST endpoint intentionally accepts anonymous opted-in events for public posts; prepared SQL and privacy/consent gates inspected. Counters are not a fraud-proof metric.
- `inc/seo.php`: post metadata and taxonomy capability/nonce checks, image permissions and output escaping.
- `inc/updater.php`: repository/HTTPS URL allowlists, fresh update metadata, hash+size verification and ZIP traversal/symlink/bomb checks; installation path and scoped core updater hooks.
- Intentional administrator ad/CMP code execution: privilege/trust/live-mode gates reviewed; not classified as an XSS flaw merely because trusted administrators can supply script.

No exploitable high-severity theme-runtime flaw was confirmed in these reviewed paths. Static review does not establish every WordPress/plugin/runtime interaction is safe.
