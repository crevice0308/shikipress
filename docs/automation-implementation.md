# 四季・記事自動化の実装

実装: `shikipress/inc/automation.php`、`assets/automation.js`、`assets/category-slug.js`、`assets/views.js`。WordPress標準APIを利用し、外部依存は任意のDeepL APIのみです。

## 判定・イベント・キャッシュ

- 季節基準はテーマ設定の `Asia/Tokyo`。WordPress全体・OS・端末のタイムゾーンを変更しません。明示的なDateTime入力もこの基準へ変換してから月を判定します。
- 自動、手動固定、管理者限定プレビューを実装。プレビューは `manage_options` とユーザーのnonceの両方が必要で、共通選定キャッシュへ保存しません。通常アクセスへnonceなしのプレビュー指定は反映されません。
- イベントは最大12件、MM-DDの開始・終了を両端含む年ごとのルールです。年またぎ、重複時の優先度、同点ID順を実装。標準の正月・クリスマスは無効です。色・ラベルを渡し、通常四季へ自動復帰します。
- 選定キャッシュは15分、有効キー上限200。季節と設定epochをキーに含め、公開・保存・削除・分類・設定変更で削除します。管理者プレビューを混ぜません。時間単位Cronが日付・イベントの変化を検出します。
- Xserver等のフルページキャッシュはテーマPHPより先に応答する場合があります。管理者ログイン、`shiki_preview_season`クエリーをキャッシュ対象外にし、日付・季節・イベント境界でサーバー側キャッシュを削除してください。テーマのtransient削除だけでホスティングのページキャッシュを更新したとは扱いません。

## カテゴリーと分類

- 管理者が実行予定を確認したセットアップだけで四季カテゴリーを作成します。対応はterm IDを保存し、再実行は冪等です。同じ名前・スラッグなら対応付け、片方だけ衝突なら作成せず管理者の選択を待ちます。既存の改名・統合はしません。削除したtermを閲覧や再有効化で復活させません。
- タイトル・タグの一致語は3点、本文の一致語は1点、3点以上を候補にします。本文は最大4万文字、各語を各欄につき1回だけ評価。ルールの根拠・点数を表示し、正解確率とは表示しません。複数候補、通年明記、未知の文章、分類ロックに対応します。
- 初期は候補のみ。任意の自動適用は、テーマ有効中に新規作成した下書きに一度だけ実行します。既存下書き、既存の手動カテゴリー、公開済み記事を自動変更しません。編集画面の明示操作は既存カテゴリーを残して選択した季節を追加します。修正・削除は標準カテゴリー欄で可能です。
- 新規カテゴリー作成画面に辞書候補、編集、再生成、採用を追加しました。採用は標準スラッグ欄へ入力するだけで、カテゴリー作成には標準の追加操作が必要です。既存カテゴリーのスラッグは変更しません。

## スラッグと外部翻訳

- 記事・固定ページのメタボックスに候補、編集、再生成、明示採用、手動固定を実装。辞書は季節の暮らしの限定語彙、固定ページ名と指定3例に対応。未知の日本語が残った場合は候補なしと明示し、翻訳を装いません。ローマ字変換機能は提供していません。
- 小文字英数字・ハイフン、最大70文字、空文字・数字のみ・予約語を処理し、採用時に`wp_unique_post_slug(..., 'publish', ...)`で下書きにも一意性を適用。公開時のWordPress標準一意性処理もそのまま動きます。
- 自動適用は新規下書きかつURL未指定が基本。手動指定したURLは保持します。公開済み・過去に公開した記事は下書きへ戻してもテーマの採用操作の対象外です。テーマ導入前から意味のあるURLを持つ下書きも保護し、公開履歴が確認できない既存URLを無断変更しません。標準WordPressの管理者による明示的なパーマリンク編集機能は妨げません。
- DeepLは初期無効。キーは `wp-config.php` の `SHIKIPRESS_DEEPL_KEY` 定数だけに保存し、設定・HTML・JS・エクスポートに含めません。API Free/Proを設定可能。編集画面で各タイトルの送信を承認してからキューを作成し、保存済みタイトル最大500文字だけを送信します。本文・タグ・サイトデータは送りません。契約と文字数により費用が発生します。
- POST `https://api-free.deepl.com/v2/translate` または `https://api.deepl.com/v2/translate`、Authorization `DeepL-Auth-Key`、JSON `text[]` / `source_lang: JA` / `target_lang: EN-US` を使用。応答の`translations[0].text`から英語候補を整形します。接続先は固定、HTTPS、リダイレクト禁止、応答16KiB制限、1試行5秒です。
- 翻訳は保存・通常閲覧の処理内で実行せず、明示承認したジョブをWP-Cronで処理。最大3回、通信失敗・429・5xxだけ60秒、120秒後に再試行。同一Cronリクエストでは最大3件、開始後12秒を過ぎると残りを延期し、通信待ちは全体最大約15秒に制限します。投稿ごとの所有者トークン付き原子的ロック、タイトルhashによる古い応答の無効化、エラーメッセージの一般化を実装。結果は候補であり自動採用しません。
- 保存済みタイトルを送信するため、エディターの未保存タイトルを使う場合は先に下書きを保存してください。ローカル環境の `DISABLE_WP_CRON` が有効なら `wp cron event run --due-now` または開発スクリプトで処理してください。

## 選定・任意の集計

- 特集の自動・手動・ハイブリッドを実装。自動は現在季節のみ、ハイブリッドは明示指定の公開記事を優先します。関連記事は現在記事を除き、共通タグかカテゴリーがあるものだけ。無関係な記事で補充しません。
- スコア: 手動指定順、優先度0〜100、季節一致40、共通タグ×20、共通カテゴリー×10、任意の集計値を最大9まで加点。同点は更新日、公開日、IDの降順。人気記事では実測集計値を第一順位にします。候補は最新更新500件を上限にし、手動指定は別に取得します。上限のため、500件より古く更新されていない自動候補が選ばれない場合があります。
- すべての枠で公開済み、パスワードなし、非除外の記事だけを再確認。枠内重複を除き、呼び出し元から除外IDを受け付けることでページ内の枠を分散します。
- 表示イベント計測は初期無効。任意に有効化し、必要な同意状態を確認できると、記事が表示されて5秒後の可視状態で同一サイトのRESTへ1件送信します。既知ボット・編集権限者を除外。IP、Cookie、訪問者ID、User-Agent原文や生ログは保存せず、投稿ID・基準タイムゾーンの日付・件数だけをカスタムテーブルへ原子的に更新します。
- 同意確認は初期有効です。広告設定のCMP IDと一致するloaded状態の公式TCF APIを使い、GDPR適用時はpublisherの目的8・9の同意、適用対象外はCMPからの明示的な判定を確認します。不在・拒否・状態不明ならイベントを送信しません。CMP自体は承認済みの広告連携かサイト既存の仕組みで読み込みます。自サイトの識別子なし集計について管理者が地域・運用要件を確認した場合に限り、明示的な確認チェックと同意ゲート無効化を保存できます。これは外部広告・外部計測の許可にはなりません。
- 計測値はユニーク訪問者数ではありません。リロード、未判定ボット、送信されなかったブラウザー等の誤差があり、悪意のある同一サイトイベント増加を完全検出する機能はありません。ランキングは過去7日/30日、15分キャッシュ。初期無効なので閲覧時の追加計測通信はありません。
- 90日より古い集計は日次最大1000行ずつ削除します。古い行が大量にある場合は削除が数日にまたがります。管理画面から即時全削除も可能です。無効化は新規記録を停止し、既存集計は保持します。
- 標準の予約投稿を再利用し、公開時のsave/statusフックでキャッシュ更新。将来・非公開・保護記事は対象外。独自Cronは同じフックを重複登録せず、テーマ切替時に解除します。集計テーブル、termとメタ・設定はテーマ切替で削除せず、将来移行に利用できます。

## 検証

専用の `SHIKI_TEST_ENV=true` サイトのみで `bash scripts/wp.sh eval-file tests/automation-integration.php` を実行します。実行結果は `tests/results/automation-integration.log` を参照してください。テストは独自印の投稿・一時termを削除し、設定を復元します。公式外部APIへの通信はモックに置き換えます。

追加検証: `node tests/automation-consent.mjs` は合成したTCF応答を利用し、CMP不在・拒否・ID不一致・状態不明・承認済み目的8/9・後からの承認・1回のみ送信を確認します。実CMPとの接続成功を示すテストではありません。

翻訳ジョブの解除・中断は状態確認で検出し、再生成を案内します。テーマを戻した後に古い「処理待ち」のまま再送信を15分間妨げることはありません。
