# 1.0.3 の固定幅広告と画面サイズ

広告枠の設定に「広告の最小幅」を追加しました。300pxの固定素材なら300、728pxなら728を指定します。0はレスポンシブタグ用です。枠の実幅が足りないと、広告コードを実行・通信する前に配信を保留します。スマートフォンや狭いサイドバーには、配信事業者が提供するレスポンシブタグを優先してください。

この設定はタグが必要とする幅を運営者が正しく指定する前提です。幅が不明な任意の外部スクリプト、配信後に自身の寸法を変更するタグ、固定広告の表示後の端末回転まで自動保証するものではありません。提供元のサイズ仕様に従って設定し、ステージングで確認してください。配信済みのiframeを切り抜く・縮小する・移動する処理は追加していません。

検証ではダミーおよび応答をローカルで置き換えた広告のみを使用します。実配信、収益計測、認定CMPのサービス固有要件、アカウント審査を通過したとの意味ではありません。詳しい実行結果は [検証記録](verification.md) を参照してください。

# 広告の導入・運用ガイド

仕様確認日：2026-10-17（日本時間）。テーマ初期値は「テスト」、広告枠は未登録、CMP・自動広告・本番許可は無効です。広告枠をテストで追加しても、実広告、外部画像、アフィリエイト計測、CMPへの通信は開始しません。

## 枠を作る

「ShikiPress → 広告」でサービス、管理名、配置、状態、端末、除外ID、本文内の挿入間隔と上限を保存します。一度保存すると次の追加行が現れます。最大24枠、1ページ全体の上限は1〜12枠です。全体「無効」または枠「無効」ではその枠を出力しません。全体がテストなら枠の本番設定も自前ダミーへ変換します。

配置は記事上、最上位H2の前後、本文中、記事下、サイドバー、フッター、手動ブロック。本文内は最上位ブロックの境界を使い、グループ・リンク・リスト・引用などの途中へ差し込みません。クラシックHTMLはDOMで最上位の段落・H2を確認します。DOM拡張がない場合、クラシック本文中だけ挿入を行いません。記事上・下は動作します。

Gutenbergで「ShikiPress 広告枠」を追加し、実在する枠IDを選択できます。記事投稿者は枠を選べますが、公式コードの登録・編集・実行許可はできません。枠のページ/カテゴリー/状態/端末/件数制限は手動ブロックにも適用されます。削除済みIDは空になります。

端末は767px以下をスマホ、768px以上をPCとします。対象外の枠はブラウザでコードを復元する前に除外します。スマホ用とPC用のタグを両方要求し、CSSだけで片方を隠す方法は使用しません。配信開始後のリサイズで既に配信された広告を強制移動・削除しません。

ダミーは通常、2秒遅延、未配信、失敗を選べます。領域と「広告 / PR」のラベルを確保します。未配信・失敗で予約領域を急に折り畳みません。

## サービス別の入力

|---|---|---|

| A8.net | 「通常広告用」公式リンク・バナーHTML全体 | サイト登録、広告主との提携、広告素材の利用条件確認 |
| もしもアフィリエイト | 公式リンク・バナーHTML、公式非同期タグ | サイト登録、提携、素材の発行 |
| afb | 公式リンク・バナーHTML/非同期タグ | サイト登録、提携と最新の素材・条件の確認 |
| バリューコマース | 公式HTML。必要に応じ公式のJavaScript非対応タグ | サイト登録、提携、使用できるタグの確認 |
| 汎用 | 管理者が承認したHTML/非同期タグ | 提供者の規約、配信地域、同意・計測要件を確認 |

成果報酬型のリンク・バナーは配信型広告と区別して表示します。公式リンクURL・画像URL・文言はテーマで生成・書き換えません。リンクだけを抜き出す変換もしません。`document.write`/`document.writeln`に依存する同期タグは未対応です。該当する場合は提供者が公式発行するHTML・非同期版を利用してください。AdSenseのネイティブ/インフィード/Multiplex用の専用パラメーター取り込みは行わないため、この標準フォームではレスポンシブ・ディスプレイを使用してください。

AdSenseは公式ローダーを一度だけ読み込み、各手動枠は別々に初期化します。自動広告は独立した設定で許可しますが、同じ公式ローダーを使うため、手動枠だけを使う場合もAdSense側で自動広告の状態を確認してください。テーマ側の設定がAdSenseアカウントを書き換えることはありません。

基本設定の公式コード取り込み欄はパブリッシャーIDだけを抽出し、貼り付けたローダーコードは保存・実行しません。手動ユニットの公式コードは枠別欄でIDを取り込みます。

他社の「共通ローダー」欄には、公式仕様で複数枠が共有できると確認したscriptの完全HTTPS URLだけを指定します。そのURLのみ一度にまとめ、枠ごとのHTML・inline初期化・異なるscriptは残します。広告ID入りの枠固有scriptを共通扱いにしないでください。すべてのscriptを一律に重複排除すると正当な複数枠が失われます。

コードを扱えるのは`manage_options`かつ`unfiltered_html`を持つ管理者です。マルチサイトでは通常スーパー管理者だけです。コードはエスケープして編集欄に表示し、管理画面では実行しません。通常投稿者のHTML制限やWordPress全体のサニタイズを変更しません。外部コードの実行許可は、そのコードがサイトで実行されることの承認です。

## 本番と認定CMP

本番配信には、全体と枠の本番状態、外部通信許可、配信地域・規約・同意条件の確認、WordPressの`WP_ENVIRONMENT_TYPE=production`が必要です。development/local/staging環境ではダミーへ置き換えます。以下のCMP確認を通るまで広告コード・画像・計測を開始しません。

Googleの公式資料では、EEA/英国/スイスのパーソナライズド広告にTCF対応のGoogle認定CMPを要求しています。テーマは独自の「同意」ボタンやlocalStorageの値を認定CMPの代わりに扱いません。認定は変わるため、公開時にもGoogleの一覧で確認してください。

1. Google「プライバシーとメッセージ」または利用する認定CMPで、対象地域・ベンダー・目的・再表示/撤回・対象ドメインを設定し、必要なメッセージを公開する。
2. 公式に発行された**CMP専用**コードを詳細欄へ登録し、信頼した外部コードとして明示的に許可する。別の方法で正規CMPが既に導入されている場合、コード欄は空でも構いません。広告ローダーをCMP専用欄へ貼って、同意前の広告要求を開始しないでください。
3. 認定一覧で確認したTCF CMP IDを設定する。各枠のベンダーIDと必要な目的IDを、契約・配信方式に合わせて確認する（AdSense初期値はGoogleベンダー755、目的1/3/4の同意を要求）。
4. TCF `addEventListener`の成功応答、CMP loaded、CMP ID一致、地域判定を確認する。GDPR適用時は完了イベント、有効なTC文字列、必要な目的/ベンダーへの同意をすべて確認する。地域未確定、CMP未設定、拒否、エラー、ベンダー未設定なら配信を保留する。
5. 実際の配信確認は所有者の承認後に手動で行い、自分の広告をクリックしない。

Google公開APIの`googlefc.callbackQueue` / `CONSENT_API_READY`と公式TCF APIに対応します。Google以外の認定TCF CMPも、正規APIと一致するIDを返せば利用できます。GDPR非適用がCMPから確定した場合は、運営者が別途確認した地域条件の下で配信します。米国州法のGPPや非TCFベンダーのAdditional Consentをテーマ独自で解釈する機能はありません。これらを必要とする配信は適切なCMP/配信サービス側で対応・検証した上で運営者が外部条件確認を行う必要があります。不明なpublisher restrictionsがある場合も保留する保守的な実装です。

撤回通知をTCFイベントで受けた場合、既に動いている広告ランタイムを終了するためページを再読み込みします。CMP側が撤回状態を保存することを確認してください。テーマは広告iframeをCSSで隠したり移動したりしません。CMPバナーの表示・配置・撤回UIは認定CMP側の機能です。

GoogleのCMPでは、通常AdSenseタグからメッセージを配信する構成があります。本テーマは同意確認前に広告ローダーを出さないため、それだけでは循環待ちになります。CMP提供者が指定する独立した同意取得コードを使用し、広告配信前にTCF APIへ有効な応答が返る構成を確認してください。広告ブロック回復タグを、無条件に同意専用タグとして流用しないでください。

## 下部4タブ・同意バナー

スマホ下部4タブの位置は維持します。初期推奨は、AdSense管理画面「広告 → サイト単位 → 編集 → オーバーレイ フォーマット」でアンカーを無効にし、意図しないインテントのアンカー等も確認することです。最新画面で名前が変わった場合は下記公式設定資料を参照してください。他社も公式の配置設定を使います。

実際の認定CMPバナーはテーマで強制移動しません。CMP側に上部表示などの公式機能があれば利用し、下部タブ、iPhoneセーフエリア、文字拡大、横向き、ソフトキーボードとの共存を実機で確認してください。ダミーの重なり検証を、外部CMP・実広告・実スマホの確認済みとは扱いません。

## ads.txt

テーマ診断はWordPressの設置ディレクトリにある既存`ads.txt`を1MB以内で読み取るだけです。外部アクセス、作成、上書き、自動追加は行いません。WordPressがサブディレクトリなら、このローカル確認とドメイン直下の到達性は一致しません。

AdSenseや各社の管理画面から、自分のサイト用に発行された正しい行を取得します。既存ファイルをバックアップし、他社の行を維持したまま必要な行を追記してドメイン直下へ設置し、`https://自分のドメイン/ads.txt`とサービス側の検証状態を確認してください。認証付きテストサイトではサービスのクローラーが到達できない場合があり、本番確認とは区別します。

## 更新・バックアップ

通常の設定エクスポートから実行可能タグを含む`ads_slots`と`ads_cmp_code`を除外します。明示的なコード移行は別操作です。インポート・復元後は広告テスト、外部通信/自動広告/CMP読み込みの無効、枠コードの未承認へ戻します。管理者が内容と外部条件を再確認して許可するまで本番配信しません。
