# 診断・リンク検査・設定移行の実装

`inc/tools.php` が診断タブ、設定バックアップタブ、および管理者専用の操作を提供します。実行時に追加ライブラリーは不要です。外部リンク取得ではDNS固定に対応するPHP cURLを必要とし、利用できない場合は取得せず「要確認」とします。

## 診断

PHP/WordPress、PHP拡張、Cron設定と1時間以上遅延したフック、検索公開設定、コアXMLサイトマップの設定、パーマリンク、キャッシュ設定、6種類の重要固定ページ、ロゴ、季節カテゴリー、広告モード、完全一致する広告タグの重複、既知のSEOプラグインを表示します。「正常」「注意」「エラー」「未確認」を分けます。

これは設定の観測です。HTTP経由のサイトマップ到達、ホスティング側Cron/CDN、広告審査や配信、CMPの適法性、文章内容の妥当性、すべての脆弱性の検出は保証しません。サーバーの絶対パス、環境変数、認証情報を表示しません。

## リンク検査

- 内部検査は管理者の操作で公開・非保護の記事と固定ページを40件ずつ確認します。記事内の重複URLはまとめ、1記事につき最大500リンクを処理します。
- 投稿ID・パーマリンク・固定ページ・カテゴリー等の公開タクソノミーとアップロードファイルをWordPress DB/ローカルファイルで照合します。内部URLをHTTP取得しません。
- 存在しない投稿ID、非公開の対象、消失したアップロード画像は「見つからない」。検索、REST、独自プラグインのルート、解決不能の一般URLは「要確認」として誤断定を避けます。結果には元記事の編集リンクが付きます。表示するURLの認証情報や秘密情報らしいクエリ値はマスクします。
- 結果は1,000件まで保存し、画面には最大200件表示します。外部キューは重複なし100 URLまで、上限超過数も表示します。実行途中の記事の削除・追加があるとoffset方式の対象は移動するため、編集が落ち着いてから「最初から再検査」を実行してください。
- 外部検査も管理者のボタン操作でのみ実行します。自動巡回・Cronからの外部通信はしません。1回2 URL、接続は直列、実行間隔60秒、HTTPタイムアウト4秒、cURL接続待ち3秒、応答本文1KB、リダイレクト2回までです。リダイレクトごとに安全検査を再実行します。
- 403/429/5xx/タイムアウトは「要確認」。404/410だけをHTTPリンク切れとして記録します。「要確認」は5分後以降にもう1回だけ再試行できます。結果確認後の再検査は内部スキャンを最初から実行します。
- 原子的なoption追加と所有トークンで検査を排他します。外部検査と内部スキャンの管理操作は同じロックを共有します。期限切れロックは90秒後に回収できます。

### SSRF対策

HTTP(S)以外、認証情報付きURL、制御文字、バックスラッシュ、特殊IP表記、末尾ドットのホスト、ローカル用ホスト、80/443以外のポートを拒否します。全A/AAAA応答を検証し、1つでもプライベート・ループバック・リンクローカル・メタデータ・予約済み・マルチキャスト・移行用アドレスがあれば取得しません。

`wp_safe_remote_get` を使用し、WordPress RequestsのtransportをcURLへ固定します。`CURLOPT_RESOLVE`で検証済み公開IPへ接続先を固定し、DNSリバインディングを抑止します。TLS証明書検証は維持し、プロキシと自動追従を無効にします。外部にURL取得REST/AJAXエンドポイントを公開しません。OSによる事前DNS照会の時間はHTTPタイムアウトとは別です。

## JSONバックアップ

形式は `format: shikipress-settings`、`schema_version: 1`、テーマ版、書き出し日時、種類、設定本体です。通常設定と実行可能な広告コードは別の書き出し操作・JSON種類で扱います。広告コードの経路には `unfiltered_html` 権限と明示チェックを追加します。

通常の書き出しはテーマdefaultsで既知のキーに限定し、秘密情報・個人情報を示すキー/値、広告publisher識別子、実行コードを除外します。APIキーはそもそも設定optionへ保存せず、設定定数の値を一切読み出しません。任意テキスト内に含まれるすべての個人情報を自動判別するものではないため、ダウンロード内容は共有前に確認してください。

インポートはファイルをサーバーへアップロードせず、512KB以内のJSON貼り付けで行います。JSON深さ、形式、schema版、既知キー、型、配列構造/件数/深さ、文字列長を検証します。データは現在の利用者専用transientへ15分だけ保持し、HTMLエスケープした事前プレビューを表示します。適用直前にも再検証します。プレビューの署名付き識別子を照合し、別タブでプレビューが入れ替わった場合は409で適用を停止します。

セクションのチェックボックスで対象を選び、各セクションの通常のsanitizerを通して保存します。選択していない設定を維持します。ただし広告事故防止のため、適用後は全体の広告モード、承認、自動広告、CMP実行、タグ信頼状態をテスト/無効に戻します。任意の閲覧集計も無効にし、同意要件を有効・確認状態を未確認に戻します。広告コードを別途移行した場合も勝手に実行しません。

適用前の全テーマ設定を非autoloadのDB optionへ1世代保存します。「適用前の設定を復元」は現在のschema/sanitizerを通し、広告を無効にした状態で戻します。記事・画像・メニュー・カテゴリー・スラッグを変更しません。JSONやスナップショットを公開ディレクトリーへ作成しません。これはWordPress全体のバックアップではありません。

## 権限

6種類のすべてのadmin-post操作が `manage_options` と操作別nonceの両方を要求します。非ログイン向けhandlerは登録しません。codeの移行には上記の追加権限も必要です。画面出力、URL、JSONプレビューを文脈に応じてエスケープします。

## 実行済みテスト

専用の実WordPressで `tests/tools-integration.php` を実行し、189 assertionsが合格しました。テストは設定・option・fixtureを後片付けします。第三者へのHTTPは送らず、外部レスポンスはWordPressのHTTPフィルターで差し替えました。cURLで実際の外部サービスへ接続する運用試験は実施していません。

検証対象: 全管理操作のnonce/権限403、匿名handler不在、危険URL/IP/混在DNS/危険redirectの取得前拒否、HTTP分類と各上限、内部検査の無通信、編集元ID、直列キューと排他/頻度、JSON形式/型/未知キー/広告経路の分離、プレビュー、選択適用、適用前保存と復元、広告の実行解除。
